Overview

moju is a physics supervision and audit library for SciML. The core is JAX-native: moju.piratio provides Groups, Models, Laws, and Operators, while moju.monitor provides ResidualEngine, build_loss, audit, and visualize. The moju.torch namespace exposes a PyTorch-facing engine and interop helpers.

Installation

pip install moju
pip install "moju[viz]"      # Plotly dashboards
pip install "moju[torch]"    # PyTorch + jax2torch support

Optional reference loaders are available with moju[ref], moju[ref_vtk], moju[ref_foam], and moju[ref_hdf5]. PDF reports use moju[report]. Moju Studio uses moju[studio] and, for HDF5/NetCDF uploads, moju[studio-science].

API at a glance

  • Groups - Dimensionless numbers such as Re, Pr, Pe, Fo, Ma, Bi, Sc, Da, and related quantities.
  • Models - Constitutive relationships such as viscosity, density, diffusivity, heat transfer, friction, and turbulence closures.
  • Laws - Residuals for heat/diffusion, wave, mass, momentum, Darcy/Brinkman, Poisson, Burgers, Schrodinger, and related equations.
  • Operators - JAX autodiff helpers: gradient, jacobian, divergence, laplacian, curl, time derivatives, advection, and symmetric gradient.
  • ResidualEngine - Build residuals, physics losses, audit logs, and visual diagnostics.
  • moju.torch - PyTorch-facing residual engine, R_eff loss helpers, nondimensionalization helpers, and JAX-law wrappers.

High-level architecture

User config and state dictionaries flow through ResidualEngine. Groups materialize dimensionless quantities into merged state. Laws produce governing residuals. Constitutive audits compare catalog models against references or implied values. Optional data/ residuals run in eval mode when state_ref is supplied. build_loss uses law residuals for optimization; audit and visualize summarize the full log.

Training and monitoring (ResidualEngine)

Path A builds state_pred from (model, params, collocation) using a state_builder. Path B passes state_pred directly, which is convenient for CFD snapshots, saved neural-operator fields, or already-computed derivatives.

In the minimal 1D slab cooling example, Path B supplies T, T_t, T_laplacian, x, t, L, and material properties directly. No finite-difference inference is needed. The Fourier conduction law runs from those fields, and the default law-linked implied audit checks Models.thermal_diffusivity(k, rho, cp) against the diffusivity implied by the law fields.

  • compute_residuals - runs laws, groups, constitutive audits, and optional eval data comparisons.
  • build_loss - cascades over law residuals only, using the same robust R_eff reduction family as the monitor log.
  • audit - reports R_norm = R_eff / scale_k, per-key scores, category scores, and overall admissibility. Governing laws use RMS R_eff with law_scale_mode="auto" term-balance scale_k by default; constitutive implied_delta / ref_delta use worst-point r_max for admissibility (logged rms stays RMS for training). Path B: state_units="dimensional" for SI uploads.
  • visualize - Plotly dashboard for residuals, category scores, spatial fields, and constitutive divergence and consistency when closure debug data is available. The constitutive row includes a Divergence heatmap (normalised as (model − implied) / (|model| + ε)) and a Constitutive Consistency line plot with spatially varying ±0.1 % / ±0.5 % / ±1 % acceptability bands and tier boundary markers centred on the model prediction.

Use monitor_training_vs_eval.md for run-mode details and law_implied_audits.md for the law-linked constitutive audit registry.

PyTorch support

Install moju[torch] to use the moju.torch namespace. It provides TorchResidualEngine, build_loss_torch, r_eff_scalar_torch, Torch-native nondimensionalization helpers, and wrap_law_torch for calling JAX laws from Torch tensors through jax2torch.

See scripts/torch_laws_jax2torch_example.py, tests/test_torch_engine.py, and tests/test_torch_interop.py for the current public surface.
